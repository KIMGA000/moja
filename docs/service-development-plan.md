# 서비스 개발 계획: 청년 마음 연결 서비스 (가칭)

> 작성일: 2026-08-04
> 근거 문서: [research-youth-isolation-mentalhealth.md](./research-youth-isolation-mentalhealth.md), [research-existing-services-competitor-analysis.md](./research-existing-services-competitor-analysis.md)
> 목적: 두 딥리서치에서 정의한 문제와 시장 공백을 실제 서비스 개발 Phase로 전환

---

## 0. 한 줄 정의

**"본인이 고립·은둔 청년/우울증 환자라고 자각하지 못했거나, 자각했어도 기존 지원사업에 신청할 힘이 없는 19~34세 청년"** 에게, 3분짜리 익명 자가진단으로 현재 상태를 알려주고 → 그에 맞는 정부·지자체 지원사업(서울시 고립은둔청년 지원사업, 마음건강 바우처 등)을 자동 매칭해 신청 문턱을 낮춰주는 웹서비스.

기존에 없던 것은 "자가진단"이나 "정책 검색" 각각이 아니라, **이 둘을 하나의 흐름(진단 → 매칭 → 신청 안내)으로 잇는 연결 레이어**다 ([competitor-analysis §3 종합 갭 분석](./research-existing-services-competitor-analysis.md#3-종합-갭-분석--우리-기획이-채울-수-있는-자리)).

---

## 1. 스코프 확정 (In / Out)

### In Scope (이번 개발 범위)
- 익명 자가진단 설문 (사회적 고립/은둔/우울 선별)
- 진단 결과 요약 화면 (경계선 위험군 여부, 유형)
- 지역(서울/그 외)·상태별 정부·지자체 지원사업 매칭 및 신청 안내(링크, 필요 서류, 절차 요약)
- 저강도 재방문 유도 체크인 (오늘 기분/한 일 짧게 기록, 로그인 없이 로컬 저장)
- 반응형 웹 (모바일 우선)

### Out of Scope (이번 개발에서 제외 — 선행 문서에서 리스크로 명시된 항목)
- 실시간 전문 상담 자체 제공
- 위기 개입(자살 위험 대응) 기능 → 발견 시 정신건강위기상담전화(1577-0199) 등 공식 채널 안내로만 대체
- AI 기반 진단·처방
- 실명 회원가입 기반 사례관리
- 온통청년 정책 데이터 자체 재구축(공식 Open API 연동으로 대체, [§4-2](#4-2-데이터-소스) 참고)

## 2. 사용자 플로우 (정보구조)

```
랜딩 페이지
  └─ "3분 자가진단 시작하기" (로그인 불필요)
       └─ 설문 (고립/은둔 13문항 + PHQ-9 기반 우울 9문항, 총 약 3분)
            └─ 결과 페이지
                 ├─ 상태 요약 (경계선 위험군 여부 + 유형: 안정/일상붕괴/회피우세/은둔 등)
                 ├─ 맞춤 지원사업 리스트 (지역 + 유형 기반 매칭)
                 │    └─ 사업별 신청 링크 / 요약 카드
                 └─ (선택) 체크인 시작하기 → 로컬 저장 기반 짧은 기록 기능
```

## 3. 기술 스택 (기존 리포지토리 기준)

현재 리포지토리는 Next.js 15 + React 19 + TypeScript 구성이 이미 되어 있다 ([package.json](../package.json)). 4주 MVP 목표에 맞춰 아래와 같이 최소 구성으로 간다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | 기존 세팅 재사용, 정적 페이지+간단 API route로 충분 |
| 상태/데이터 저장 | 로컬스토리지(체크인) + 정적 JSON/TS 파일(지원사업 매칭 DB) | 회원가입·서버 DB 없이도 MVP 요건 충족, 운영 비용 최소화 |
| 배포 | Vercel (Next.js 기본 호스팅) | 무료 티어로 4주 내 배포·검증에 충분 |
| 외부 연동 | 온통청년 Open API (선택적, Phase 2 후반) | 정책 데이터 신뢰성 확보, 자체 재구축 비용 절감 ([온통청년 오픈API 안내](https://www.youthcenter.go.kr/cmnFooter/openapiIntro/oaiDoc), [공공데이터포털 등록 정보](https://www.data.go.kr/data/15143273/openapi.do)) |

## 4. Phase별 개발 계획

전체 약 4주(20 영업일) 기준. 각 Phase는 순차적이지만 Phase 2와 3 일부는 병행 가능.

### Phase 0. 기획 확정 & 콘텐츠 설계 (개발 착수 전, 2~3일)

- **목표**: 개발에 들어가기 전 "무엇을 보여줄지" 확정. 이 Phase가 부실하면 이후 모든 Phase가 흔들림.
- **작업**
  - 자가진단 문항 확정: 한국청소년정책연구원의 사회단절·회피·불규칙생활 13문항 척도 + PHQ-9 우울 9문항을 어떻게 재구성할지 확정 ([research-youth-isolation-mentalhealth.md §4-2](./research-youth-isolation-mentalhealth.md#4-2-핵심-기능-4주-mvp-기준))
  - 위험군 판별 로직(점수 구간별 유형 분류) 설계 — 가능하면 정신건강 전문가 자문 1회 이상 확보
  - 매칭 대상 지원사업 목록 1차 확정: 서울시 고립·은둔청년 지원사업, 서울시 청년 마음건강 지원사업, 정신건강 심리상담 바우처사업(전국) 등 우선 3~5개로 시작 ([research-youth-isolation-mentalhealth.md §3-1](./research-youth-isolation-mentalhealth.md#3-1-공공-지원사업-현황))
  - 와이어프레임(화면 흐름) 확정
- **산출물**: 확정된 문항지, 채점/분류 로직 문서, 지원사업 매칭 DB 초안(스프레드시트), 와이어프레임
- **완료 기준**: 개발자가 별도 질문 없이 화면을 만들 수 있는 수준의 스펙 확정

### Phase 1. 자가진단 플로우 구현 (1주차)

- **목표**: 랜딩 → 설문 → 결과 요약까지의 핵심 경로를 동작하게 만든다.
- **작업**
  - 랜딩 페이지 (서비스 소개, 익명성 강조 문구, CTA)
  - 설문 컴포넌트 (문항 진행률 표시, 뒤로가기 지원, 3분 내 완료 가능한 UX)
  - 채점 로직 구현 (Phase 0에서 확정한 로직을 함수로 구현, 유닛 테스트로 경계값 검증)
  - 결과 요약 화면 (유형별 안내 문구, 위험군 여부에 따라 다음 CTA 분기)
- **완료 기준**: 문항 입력 → 결과 화면까지 로그인 없이 끝까지 동작, 새로고침해도 개인정보가 서버에 남지 않음(익명성 검증)

### Phase 2. 지원사업 매칭 & 연결 기능 (2주차)

- **목표**: 결과에 따라 실제로 신청 가능한 지원사업을 보여주고, 신청까지의 절차를 줄여준다.
- **작업**
  - 지원사업 매칭 DB를 정적 데이터 형태로 구현 (지역 × 위험 유형 × 연령 조건)
  - 결과 화면과 매칭 로직 연결 (해당 유형에 맞는 사업만 필터링해 카드로 노출)
  - 각 사업 카드에 신청 링크, 필요 서류, 소요 시간 등 "신청 문턱을 낮추는" 요약 정보 포함
  - (여유 있으면) 온통청년 Open API 연동 검토 — 회원가입 및 인증키 발급 필요하므로 일정에 여유가 없으면 Phase 5(확장)로 이월
- **완료 기준**: 최소 3개 이상 실제 지원사업이 정확한 조건으로 매칭되어 노출, 신청 링크 클릭 시 실제 신청 페이지로 정상 이동

### Phase 3. 재방문 유도 & 완성도 (3주차)

- **목표**: 낙인 우려를 낮추는 디테일과, 1회성 방문을 넘어선 재방문 장치를 추가한다.
- **작업**
  - 저강도 체크인 기능 (오늘 기분 1탭 기록 + 짧은 메모, 로컬스토리지 저장, 서버 전송 없음)
  - 위기 신호 감지 시 안내 문구 (자살 위험 관련 문항에 특정 응답 시 1577-0199 등 공식 위기상담 채널 즉시 노출) — Out of Scope로 규정한 "위기 개입"과의 경계를 명확히: 우리는 개입하지 않고 공식 채널로 안내만 함
  - 반응형/모바일 최적화, 접근성(색약 대비, 스크린리더 대응) 점검
  - 카피 톤 다듬기 (낙인·부담을 낮추는 문구로 전체 리라이팅)
- **완료 기준**: 모바일 기기에서 전체 플로우 이상 없이 동작, 위기 신호 케이스에 대한 안내 문구 노출 확인

### Phase 4. QA, 콘텐츠 검수 & 배포 (4주차)

- **목표**: 실제 사용자에게 노출 가능한 수준으로 마무리하고 배포한다.
- **작업**
  - 콘텐츠 검수: 자가진단 문항·결과 문구가 실제 임상적으로 오해를 유발하지 않는지 재확인 (가능하면 외부 전문가 리뷰)
  - 지원사업 정보 최신성 재확인 (신청 기간, 예산 소진 여부 등 변경 가능성이 높은 정보 재점검)
  - 크로스 브라우저/디바이스 QA
  - Vercel 배포, 도메인 연결
  - 초기 트래픽 확보 채널 준비 (대학 커뮤니티, 청년센터 협조 요청 등 — 선행 문서에서 지적된 "타겟 도달 문제"에 대한 최소 대응)
- **완료 기준**: 실 서비스 URL로 배포 완료, 핵심 플로우 QA 체크리스트 통과

## 5. Phase 이후 확장 아이디어 (이번 개발 범위 밖, 참고용)

- 온통청년 Open API 정식 연동으로 매칭 DB 자동 갱신
- 안무서운회사, 자립지원센터 내비두 등 오프라인 소셜벤처와의 연계 신청 기능 ([research-existing-services-competitor-analysis.md §3](./research-existing-services-competitor-analysis.md#3-종합-갭-분석--우리-기획이-채울-수-있는-자리))
- 진단 결과 기반 콘텐츠 추천(마음건강 앱 사례 참고) 추가
- 익명 피어 커뮤니티 기능

## 6. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| 자가진단 문항의 임상적 신뢰도 부족 | Phase 0에서 전문가 자문 최소 1회 확보, 서비스 내 "진단이 아닌 자기 이해를 돕는 선별 도구"임을 명시 |
| 위기 상황(자살 위험) 발생 시 책임 소재 | 직접 개입하지 않고 공식 위기상담 채널로만 안내, 이용약관에 명시 |
| 지원사업 정보의 최신성 유지 비용 | Phase 4에 최신성 재확인 절차 포함, 장기적으로는 Open API 연동으로 자동화 |
| 초기 트래픽 확보 어려움 (타겟이 스스로 접근을 꺼림) | 오프라인 소셜벤처·청년센터와의 협력 채널을 Phase 4부터 준비 |
