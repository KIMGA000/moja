# 서비스 개발 계획: 사장님 지원사업 알리미 (가칭)

> 작성일: 2026-08-14
> 근거 문서: [research-foodservice-smallbiz-support-gap.md](./research-foodservice-smallbiz-support-gap.md), [research-foodservice-smallbiz-competitor-analysis.md](./research-foodservice-smallbiz-competitor-analysis.md)
> 목적: 두 딥리서치에서 정의한 문제와 시장 공백을 실제 서비스 개발 Phase로 전환
> 비고: 기존 리포지토리(청년 마음 연결 서비스)와는 별개의 신규 프로젝트로 기획

---

## 0. 한 줄 정의

**"자격이 있는 정부·지자체 지원사업을 몰라서, 혹은 영업 중 서류·신청 절차를 처리할 시간·디지털 역량이 없어서 놓치는 요식업 소상공인"** 에게, 1분짜리 익명 자가진단(업종·매출·지역·사업자 등록 기간)으로 → 지금 신청 가능한 정책자금·배달비 지원·위생등급 연계·희망리턴패키지 등을 자동 매칭해 보여주고, 마감일이 임박하면 알려주는 웹서비스.

기존에 없던 것은 "지원사업 검색"이나 "AI 매칭 엔진" 각각이 아니라, **요식업이라는 업종에 특화해 진단→매칭→신청 안내를 하나로 잇는 연결 레이어**다 ([competitor-analysis §3 종합 갭 분석](./research-foodservice-smallbiz-competitor-analysis.md#3-종합-갭-분석--우리-기획이-채울-수-있는-자리)).

---

## 1. 스코프 확정 (In / Out)

### In Scope (이번 개발 범위)
- 익명 자가진단 (업종 세분류, 월매출 구간, 사업자 등록 기간, 지역, 배달앱 이용 여부 등 5~7문항)
- 진단 결과 기반 맞춤 지원사업 리스트 (정책자금, 배달비 지원, 위생등급 연계, 희망리턴패키지 등)
- 사업별 신청 안내 카드 (신청 링크, 필요 서류, 마감일, 소요 시간 요약)
- 관심 사업 저장 + 마감 임박 알림 (로그인 없이 로컬 저장 또는 최소 연락처 기반)
- 반응형 웹 (모바일 우선, 고령 사용자 고려한 큰 글씨·단순 UI)

### Out of Scope (이번 개발에서 제외)
- 신청서류 작성 대행, 사업계획서 자동생성
- 세무·법률 자문, 자금 심사 개입
- 실명 회원가입 기반 사례관리
- 정부 공고 데이터 자체 재구축(공식 Open API/공공데이터 연동으로 대체)
- 신청 완료·수령까지의 전체 대행 (신청 페이지로 안내까지만 담당)

---

## 2. 사용자 플로우 (정보구조)

```
랜딩 페이지
  └─ "1분 안에 내가 받을 수 있는 지원금 확인하기" (로그인 불필요)
       └─ 자가진단 (업종/매출/사업자등록기간/지역/배달앱 이용여부, 총 5~7문항)
            └─ 결과 페이지
                 ├─ 맞춤 지원사업 리스트 (정책자금/배달비/위생등급/희망리턴패키지 등)
                 │    └─ 사업별 카드 (신청 링크, 필요 서류, 마감일)
                 └─ (선택) 관심 사업 저장 → 마감 임박 알림 신청
```

## 3. 기술 스택 제안

기존 리포지토리(청년 마음 연결 서비스)와 별개의 신규 프로젝트이므로, 동일한 검증된 스택을 재사용하되 새 저장소/새 배포로 분리한다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + React + TypeScript | 정적 페이지+간단 API route로 MVP 요건 충족, 기존 프로젝트와 동일한 스택이라 재사용 가능한 컴포넌트 패턴 활용 |
| 상태/데이터 저장 | 로컬스토리지(관심 사업 저장) + 정적 JSON/TS 파일(지원사업 매칭 DB) | 회원가입·서버 DB 없이도 MVP 요건 충족 |
| 배포 | Vercel | 무료 티어로 빠른 배포·검증 |
| 외부 연동 | 기업마당(bizinfo.go.kr) 공공데이터 API, 공공데이터포털 소상공인 정책자금 API (선택적, Phase 2 후반) | 지원사업 데이터 신뢰성 확보, 자체 재구축 비용 절감 |

## 4. Phase별 개발 계획

### Phase 0. 기획 확정 & 콘텐츠 설계 (개발 착수 전)

- **목표**: "어떤 지원사업을 어떤 조건으로 보여줄지" 확정.
- **작업**
  - 자가진단 문항 확정 (업종 세분류, 매출 구간, 사업자 등록 기간, 지역, 배달앱 이용 여부)
  - 매칭 로직 설계 (문항 응답 → 지원사업 필터링 규칙)
  - 매칭 대상 지원사업 목록 1차 확정: 소상공인 정책자금, 배달·택배비 지원, 위생등급 연계 지원, 희망리턴패키지 등 우선 5~7개로 시작 ([research-foodservice-smallbiz-support-gap.md §2-2](./research-foodservice-smallbiz-support-gap.md#2-2-지원사업-규모-사업은-존재함을-보여주는-근거))
  - 와이어프레임(화면 흐름) 확정
- **산출물**: 확정된 문항지, 매칭 로직 문서, 지원사업 매칭 DB 초안(스프레드시트), 와이어프레임
- **완료 기준**: 개발자가 별도 질문 없이 화면을 만들 수 있는 수준의 스펙 확정

### Phase 1. 자가진단 플로우 구현

- **목표**: 랜딩 → 자가진단 → 결과 리스트까지의 핵심 경로를 동작하게 만든다.
- **작업**
  - 랜딩 페이지 (서비스 소개, "1분이면 확인" 강조 문구, CTA)
  - 자가진단 컴포넌트 (문항 진행률 표시, 뒤로가기 지원, 큰 글씨·단순 UI로 고령 사용자 고려)
  - 매칭 로직 구현 (Phase 0에서 확정한 규칙을 함수로 구현, 유닛 테스트로 경계값 검증)
  - 결과 리스트 화면 (매칭된 지원사업 카드 나열)
- **완료 기준**: 문항 입력 → 결과 화면까지 로그인 없이 끝까지 동작

### Phase 2. 지원사업 매칭 DB & 신청 안내 카드

- **목표**: 매칭된 각 지원사업에 대해 실제 신청까지의 절차를 명확히 안내한다.
- **작업**
  - 지원사업 매칭 DB를 정적 데이터 형태로 구현 (업종 × 매출구간 × 지역 × 사업자등록기간 조건)
  - 각 사업 카드에 신청 링크, 필요 서류, 마감일, 예상 소요 시간 포함
  - (여유 있으면) 기업마당/공공데이터포털 API 연동 검토
- **완료 기준**: 최소 5개 이상 실제 지원사업이 정확한 조건으로 매칭되어 노출, 신청 링크 클릭 시 실제 신청 페이지로 정상 이동

### Phase 3. 재방문 유도 & 완성도

- **목표**: 마감을 놓치지 않게 하는 장치와, 고령 사용자를 고려한 접근성을 다듬는다.
- **작업**
  - 관심 지원사업 저장 + 마감 임박 알림 (로컬스토리지 또는 최소 연락처 기반)
  - 반응형/모바일 최적화, 접근성(큰 글씨 모드, 색약 대비) 점검
  - 카피 톤 다듬기 (행정 용어를 쉬운 말로 재작성)
- **완료 기준**: 모바일 기기에서 전체 플로우 이상 없이 동작

### Phase 4. QA, 콘텐츠 검수 & 배포

- **목표**: 실제 사용자에게 노출 가능한 수준으로 마무리하고 배포한다.
- **작업**
  - 지원사업 정보 최신성 재확인 (신청 기간, 예산 소진 여부 등 변경 가능성이 높은 정보 재점검)
  - 크로스 브라우저/디바이스 QA
  - Vercel 배포, 도메인 연결
  - 초기 트래픽 확보 채널 준비 (배민아카데미·외식업중앙회 등 기존 접점과의 협력 요청 — [competitor-analysis §3](./research-foodservice-smallbiz-competitor-analysis.md#3-종합-갭-분석--우리-기획이-채울-수-있는-자리) 참고)
- **완료 기준**: 실 서비스 URL로 배포 완료, 핵심 플로우 QA 체크리스트 통과

## 5. Phase 이후 확장 아이디어 (이번 개발 범위 밖, 참고용)

- 기업마당 공공데이터 API 정식 연동으로 매칭 DB 자동 갱신
- 배달앱(배민·쿠팡이츠)과의 연계 — 배달비 지원사업 집행 파트너십 전례 활용
- 손실보상금 등 "이미 자격이 있었는데 놓친" 사업에 대한 소급 확인 기능
- 세무사·노무사 연계 신청 대행 서비스 (유료 옵션)

## 6. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| "미신청 규모"를 뒷받침하는 공식 통계 미확보 | Phase 0~4 전반에서 이 수치를 마케팅 근거로 사용하지 않고, 대신 폐업률·고령화 등 검증된 통계로 문제의 시급성을 설명 ([research-foodservice-smallbiz-support-gap.md §2-3](./research-foodservice-smallbiz-support-gap.md#2-3-왜-신청에-실패하는가--구조적-원인)) |
| 지원사업 정보의 최신성 유지 비용 | Phase 4에 최신성 재확인 절차 포함, 장기적으로는 공공데이터 API 연동으로 자동화 |
| 타겟(고령·디지털 취약 사장님) 도달 어려움 | 배민아카데미, 외식업중앙회 등 기존 오프라인 접점과의 협력 채널을 Phase 4부터 준비 |
| 범용 매칭 엔진(지원금AI, 펀디 등)과의 기술 격차 | 매칭 알고리즘 자체보다 요식업 도메인 특화(업종 세분류, 배달비/위생등급 조건)로 차별화 |
