## 1. 보안 — 최우선

- [ ] **`announcements_all` 뷰 RLS 우회 (확인함, 아직 안 고쳐짐)**
  `supabase/schema.sql`에 `security_invoker = on` 설정이 없음. anon 키로 이 뷰를 직접 조회하면
  미승인(`pending`) 공고까지 노출된다. 개별 테이블은 RLS로 막혀 있지만 뷰는 그 정책을 우회한다.
  ```sql
  alter view announcements_all set (security_invoker = on);
  ```
- [ ] **`CRON_SECRET` 환경변수 실제로 설정됐는지 확인**
  `app/api/sync-announcements/route.ts` 코드는 이미 대응돼 있음(`process.env.CRON_SECRET` 체크).
  Vercel 프로젝트 환경변수에 값이 들어있는지만 확인하면 됨 — 안 넣었으면 크론 라우트가 인증 없이 열려있는 상태.

## 2. 판정 정확도 — 설계 부채

- [ ] **`realMatch.ts`가 여전히 원문 텍스트 정규식 재검사 방식**
  검수자가 DB의 `classify.ts` 분류 컬럼(`region_scope`/`requires_enrolled`/`interest_categories`)을 고쳐도
  실제 매칭결과 탭 판정에는 반영 안 됨. `realMatch.ts`를 DB 컬럼 기반으로 전환하는 게 근본 해결책.
- [ ] **재학여부/취업상태 분리가 실제 판정 로직엔 아직 안 들어감 (신규 확인)**
  이번 세션에 `enrollmentStatus`/`employmentStatus`를 독립 필드로 분리했지만,
  `realMatch.ts`에는 `employmentStatus`를 참조하는 코드가 전혀 없음(grep 결과 0건).
  즉 취업 상태는 프로필 카드에 표시만 되고, 실제 공고 매칭에는 아직 반영되지 않음.
- [ ] **`app/data/eligibility.ts`의 `evaluateAll`(21개 정적 규칙 엔진)이 죽은 코드로 확인됨 (신규 확인)**
  `evaluateAll`을 호출하는 곳이 코드 전체에 단 한 군데도 없음 — 이전 피벗 때 쓰던 정적 판별기가
  `realMatch.ts`(동적 DB 매칭)로 대체된 뒤 남아있는 잔재로 보임. 정리(삭제)하거나,
  "확정 판정 대신 uncertain 처리" 원칙이 필요하면 이 로직을 되살려 연결할지 팀 결정 필요.
- [ ] `youthCenter` 소스는 지역코드(zipCd)→지역명 변환이 없어서 거주지 필터가 안 걸림
- [ ] `protectionEndTypesApplicable`가 늘 5종 전부 반환하는 placeholder (본문에서 배제 신호 찾는 로직 없음)
- [ ] `description_tags` 키워드 사전(24개)이 임의 큐레이션이라 빠진 단어가 있을 수 있음

## 3. 검수/운영 워크플로우

- [ ] **검수 UI가 없음** — 지금은 모든 신규/기존 공고가 자동 `approved` 처리되도록 방금 바꿨는데(원래 "몇 개가 안 불러와지는" 버그 긴급 수정),
  이 정책일수록 잘못된 공고를 걸러낼 검수 화면이 더 필요해짐. 지금은 Supabase SQL Editor에서 수동으로만 가능.
- [ ] **`feature/review-pipeline` 브랜치, 아직 `dev`에 병합 안 됨 (재확인함, 여전히 원격에 존재)**

  방향이 충돌할 가능성이 있음. 병합 전에 팀원과 조율 필요.
