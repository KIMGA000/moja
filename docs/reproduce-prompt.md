# 모자(MOJA) 재현용 프롬프트

아래 "프롬프트 원문" 섹션 전체를 그대로 복사해서 **새 Claude Code 대화**에 붙여넣으면, 이번에
만든 것과 같은 구조의 앱을 처음부터 순서대로 만들 수 있어요. 각 단계가 끝나면 다음 단계로
넘어가라고 하면 되고, 한 번에 다 시켜도 순서대로 처리해줘요.

**API 키는 지워뒀어요.** 프롬프트 안에 `.env.local` 변수 이름만 있고 실제 키 값은 없습니다.
아래 "필요한 API 키" 표를 보고 각자 발급받은 키로 채워 넣으면 됩니다.

## 프롬프트 원문 (아래를 통째로 복사)

```
자립준비청년(보호시설·위탁가정에서 보호가 종료되어 자립을 준비/시작한 청년)을 위한 웹
서비스 "모자(MOJA)"를 Next.js 15(App Router) + React 19 + TypeScript로 만들 거야.
아래 단계를 순서대로 진행해줘. 각 단계가 끝나면 타입체크(npx tsc --noEmit)와 브라우저
확인까지 하고 다음 단계로 넘어가줘.

────────────────────────────────────
[1단계] 목업 데이터 기반 매칭 프로토타입
────────────────────────────────────
거주 지역(서울/그 외), 보호종료 상태(보호종료 예정 또는 시설·위탁가정에 있음 / 보호종료
후 5년 이내 / 보호종료 후 5년 초과), 관심분야(주거/생활비·수당/자산형성/취업/심리·정서/
멘토링·교육/종합상담·정보, 복수선택)를 고르면 목업 공고 데이터에서 조건에 맞는 걸 보여주는
간단한 화면을 만들어줘. 서비스 카피는 "몰라도 괜찮아, 모자가 챙겨줄게."로 하고, 저장(⭐
북마크) 기능은 localStorage에만 저장해줘 (서버 전송 안 함).

────────────────────────────────────
[2단계] 정부 공공데이터 API 7종 연동
────────────────────────────────────
아래 7개 공공 API를 실시간으로 불러와서 공통 타입(WelfareItem: source, servId, servNm,
servDgst, org, region?, themes, lifeStages, targetTraits?, sprtCycNm?, srvPvsnNm?,
deadline?, onlineApplicable?, applyMethod?, contact?, link)으로 합쳐줘.

1. 한국사회보장정보원 중앙부처복지서비스 — XML, "자립"과 "청년" 두 키워드로 각각 검색 후
   합치고 중복 제거
2. 한국사회보장정보원 지자체복지서비스 — 위와 동일
3. 정부24(보조금24) 대한민국 공공서비스(혜택) 정보 — JSON, 위와 동일하게 키워드 검색
4. 국토교통부 마이홈포털 공공임대주택 모집공고 — odcloud.kr 플랫 JSON 형식, 키워드 검색
   없이 전체 수집 (전세임대는 현실성이 낮으니 임대 형태별로 분류만 해줘)
5. 고용24 국민내일배움카드 훈련과정 — XML, 전체 수집
6. 고용24 구직자취업역량강화프로그램 — XML, 전체 수집
7. 고용24 일학습병행 훈련과정 — XML, 전체 수집

API 키는 .env.local에 아래 이름으로 넣어놨어 (실제 값은 내가 채워넣을게):
WELFARE_API_KEY, WORK24_TOMORROW_CARD_KEY, WORK24_JOBSEEKER_PROGRAM_KEY,
WORK24_DUAL_TRAINING_KEY, WORK24_COMMON_CODE_KEY

각 소스는 응답 형식이 다 다르니(XML 블록 구조, JSON envelope, odcloud 플랫 JSON) 소스별로
매퍼 함수를 만들어서 공통 타입으로 변환해줘. 공용 fetch/파싱 로직은 lib/govApis.ts 같은
모듈로 분리해서 여러 API 라우트에서 재사용할 수 있게 해줘. 페이지네이션도 끝까지 돌려서
전체 건수를 다 가져와줘.

"자립준비청년 관련"인지 텍스트 키워드로 판별하는 함수와, "청년 관련"인지 판별하는 함수를
각각 만들어서, 화면에서 3단계 토글(자립준비청년 관련만 / 청년 관련만 / 전체)로 볼 수 있게
해주고, 소스별로 전체 건수 대비 관련 건수가 몇 건인지도 보여줘. 소스 카드를 누르면 그
소스만 필터링해서 볼 수 있게 해줘.

지역명 매칭할 때 주의: 축약형 지역명(충북/충남/경북/경남/전남)은 정식 명칭(충청북도/
충청남도/경상북도/경상남도/전라남도)의 부분 문자열이 아니니까, 정식 명칭을 먼저 검사하고
못 찾으면 축약형을 검사하는 순서로 만들어줘.

────────────────────────────────────
[3단계] 자격 정밀 진단 엔진
────────────────────────────────────
12개 질문(생년월일, 보호종료 유형[만 18세 종료/연장 보호종료/조기 보호종료/재보호 후
종료/현재 보호중], 조기종료면 원가정 복귀 여부, 보호종료(예정)일, 현재 상태[대학재학/
대학원재학/취업/미취업/기타], 거주 지역, 주택 소유 여부, 혼인 여부, 기초생활수급 여부,
차상위 본인부담 경감 여부, 현재 받고 있는 지원, 관심분야)으로 온보�딩 마법사를 만들고,
아래 같은 실제 자립준비청년 지원 제도들(약 20개)을 룰 기반으로 평가해서 "가능성 높음 /
확인 필요 / 해당 안 됨"으로 분류하고, 기한(D-day)이 있으면 임박한 순으로 정렬해줘. 제도
간 중복수급 충돌(예: 국가장학금 vs 지자체 등록금 지원)도 미리 경고해줘.

포함할 제도 예시: 자립수당, 자립정착금, LH 전세임대/매입임대주택, 희망디딤돌센터 주거
서비스, 디딤씨앗통장 만기지급, 청년내일저축계좌, 정신건강 심리상담 바우처, 자립지원
전담기관 사례관리, 자립정보ON 통합상담, 국민취업지원제도, 국민내일배움카드, 멘토링
지원사업, 지자체 청년 마음건강 지원, 국가장학금, 대학생 근로장학금, 청년월세지원, 의료비
지원, 지자체 등록금 지원, 긴급복지지원, 생계급여. 각 제도의 자격 조건은 MVP 근사치로
작성하고, 법령이 자주 바뀌는 항목은 "확정"이 아니라 "확인 필요"로 처리해줘.

그 다음, 이 진단 결과를 목업이 아니라 2단계에서 만든 실시간 API 데이터 기준으로 다시
구성해줘. 즉 온보딩 답변을 실제 공고 텍스트(지역/보호기간/재학여부/무주택/기초생활수급/
현재 보호중 여부 등)와 대조해서 매칭하는 방식으로 바꿔줘.

────────────────────────────────────
[4단계] Supabase DB 저장 · 검수 파이프라인
────────────────────────────────────
API에서 "자립" 키워드로 불러온 결과를 검수하고 중복을 거를 수 있도록 Supabase에 저장하고
싶어. 소스별(중앙부처/지자체/정부24/주거/훈련/구직자프로그램/일학습병행, 총 7개)로 테이블을
따로 만들고, 각 테이블에 아래를 저장해줘.

- 원문 필드: source_id(고유), serv_nm, serv_dgst, org, region, target_traits, deadline,
  link, raw_data(jsonb)
- 온보딩 질문과 매칭할 조건을 저장 시점에 미리 계산해서 컬럼으로 저장: 자립준비청년 관련
  여부, 청년 관련 여부, 보호기간 제한(예: "5년 이내"면 5), 재학 요건 언급 여부, 무주택
  요건 언급 여부, 기초생활수급 요건 언급 여부, "이미 보호종료" 전제 여부, 지역 범위(전국이면
  null), 관심분야 카테고리 배열, 해당하는 보호종료 유형 배열(만18세종료/연장종료/조기종료/
  재보호후종료/현재보호중 5종 중)
- 검수 워크플로우 컬럼: review_status(pending/approved/rejected), 중복 표시(어느 소스의
  어떤 글과 중복인지), 검수자, 검수일시, 검수 메모

pg_trgm 확장으로 이름 유사도 기반 중복 탐지 인덱스를 걸어주고, RLS로 review_status가
approved인 것만 익명 사용자가 조회할 수 있게 해줘. 7개 테이블을 한 번에 조회하는 통합
뷰도 만들어줘.

동기화 API 라우트를 만들어서 7개 소스를 다 가져와 upsert해줘. 중앙부처/지자체/정부24는
필터링 없이 "자립" 키워드 검색 결과를 그대로 저장(노이즈는 사람이 나중에 검수), 나머지
4개는 서버 단 키워드 검색이 안 되는 API라(수백~수만 건 규모) 미리 "자립준비청년 관련"
텍스트 필터를 거쳐서 저장해줘. 재동기화할 때 검수 상태를 덮어쓰지 않도록 upsert 페이로드에
검수 관련 컬럼은 넣지 말아줘.

Supabase 연결은 공개 anon 클라이언트와 서버 전용 서비스 롤 클라이언트를 분리해서 만들어줘.
환경변수는 NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY,
SUPABASE_SERVICE_ROLE_KEY로 넣어놨어.

이 단계의 스키마 SQL은 내가 Supabase 대시보드 SQL Editor에서 직접 실행해야 하니, 실행할
전체 SQL을 파일로 만들어서 알려줘.

────────────────────────────────────
[5단계] UI/UX 리디자인
────────────────────────────────────
지금 온보딩·결과 화면 디자인을 첨부하는 목업 2세트를 기준으로 다시 만들어줘. (여기서
목업 이미지 2장 — 로그인/회원가입 화면, "보육원·그룹홈·위탁가정에서 지낸 적이 있나요?"
질문 화면, "이곳은 시설·위탁가정에서 지낸 분들을 위한 서비스예요" 안내 화면, "보호가 끝난
때가 언제인가요?" 연도/월 선택 + 자동계산 화면 — 를 함께 첨부해줘.)

디자인 방향: 배경은 흰색, 카드는 옅은 테두리를 가진 화이트 박스, 버튼은 완전히 둥근
필(pill) 형태의 검정 버튼, 질문 카테고리는 보라색/청록색 배지로 표시, 포인트 컬러로
라임그린 하나를 정해서 로고·프로그레스바·강조 텍스트에만 아껴 써줘.

온보딩 맨 앞에 "보육원·그룹홈·위탁가정에서 지낸 적이 있나요?" 게이트 질문을 추가해서,
"아니오"를 고르면 이 서비스 대상이 아니라는 안내와 함께 대체 서비스(온통청년, 복지로)로
안내하는 화면을 보여주고, "예"를 고르면 바로 다음 질문으로 진행하게 해줘.

보호종료일 입력은 정확한 날짜 대신 연도·월 드롭다운으로 받고, 입력하는 즉시 "보호종료 후
경과 기간"과 "5년 기한까지 남은 기간"을 자동 계산해서 큰 숫자로 보여줘.

로그인/회원가입 화면은 실제 계정 기능(회원가입/서버DB/커뮤니티)은 아직 만들지 말고,
비주얼만 참고해서 지금 있는 랜딩 화면에 반영해줘 (계정 없이 바로 진단 시작하는 흐름은
유지).

────────────────────────────────────
[6단계] Vercel 배포
────────────────────────────────────
Vercel CLI로 로그인 상태를 확인하고, .env.local에 있는 환경변수 전부를 Vercel 프로젝트의
Production/Preview 환경에 등록한 다음, 프로덕션으로 배포해줘. 배포 후 실제 URL에
접속해서 랜딩 페이지와 /api/welfare 응답이 정상인지 확인해줘.
```
