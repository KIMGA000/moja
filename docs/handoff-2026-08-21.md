## 1. 프로젝트 개요

- **서비스명**: 모자(MOJA), 팀명: 파란만 (AX-Ton 해커톤)
- **대상 사용자**: 자립준비청년 (보호시설·위탁가정에서 보호가 종료되어 자립을 준비/시작한 청년)
- **핵심 가치**: 흩어진 정부 지원 공고를 실시간으로 모아 조건에 맞는 것만 보여주고, 자격 여부를
  진단해주고, 또래와 이야기 나눌 수 있는 익명 커뮤니티도 제공
- **기술 스택**: Next.js 15(App Router) + React 19 + TypeScript, Supabase(PostgreSQL + Auth),
  Vercel 배포

## 2. 지금까지 만든 기능

### 2-1. 공공데이터 API 연동 (8개 소스)
`lib/govApis.ts`에 공용 fetch/파싱 로직이 있고, `app/api/welfare/route.ts`(화면 미리보기)와
`app/api/sync-announcements/route.ts`(DB 저장) 둘 다 여기서 가져다 씀.

| 소스 키 | 실제 API |
|---|---|
| `central` | 한국사회보장정보원 · 중앙부처복지서비스 |
| `local` | 한국사회보장정보원 · 지자체복지서비스 |
| `gov24` | 정부24(보조금24) |
| `housing` | 마이홈포털 공공임대주택 모집공고 |
| `training` | 고용24 · 국민내일배움카드 훈련과정 |
| `jobseekerProgram` | 고용24 · 구직자취업역량강화프로그램 |
| `dualTraining` | 고용24 · 일학습병행 훈련과정 |
| `youthCenter` | 온통청년(youthcenter.go.kr) · 청년정책(`getPlcy`) — **오늘 새로 추가** |

- `isAboutCareLeavers`/`isAboutYouth` 텍스트 키워드 함수로 "자립준비청년 관련"/"청년 관련" 분류.
- ⚠️ `youthCenter` 소스는 `zipCd`(지역코드)를 지역명으로 변환하는 로직이 없어서, 이 소스의
  공고들은 거주지 필터링이 안 걸러집니다 (알려진 한계, 나중에 보완 필요).
- ⚠️ 온통청년의 다른 API인 청년콘텐츠(`getContent`)·청년센터(`getSpace`)는 데이터 모양이
  완전히 달라서(공고가 아니라 게시물/오프라인 공간 정보) 아직 연동 안 함 — 사용자가 "지금은
  보류"라고 결정함.

### 2-2. 자격 정밀 진단
- `app/data/eligibility.ts`: 온보딩 12문항 타입/라벨 + 21개 제도 룰(목업 데이터, 지금은
  실제 매칭에는 안 쓰임 — 화면 UI 타입 정의 용도로만 남아있음)
- `app/data/realMatch.ts`: 실제 API 데이터(`WelfareItem[]`)를 온보딩 답변과 텍스트 규칙으로
  매칭해서 eligible/uncertain/ineligible로 분류. **실제 진단 결과는 이 파일 기준.**
- `app/components/EligibilityFlow.tsx`: 온보딩 마법사 + 결과 화면. 오늘 추가/수정된 것:
  - **Q1 게이트 질문** "보육원·그룹홈·위탁가정에서 지낸 적이 있나요?" — 아니오 선택 시 대상 아님
    안내 화면(온통청년/복지로 링크)으로 분기
  - 생년월일을 연/월/일 드롭다운으로 (예전엔 `<input type="date">`라 6자리 연도 입력되는 버그 있었음)
  - 보호종료(예정)일 연/월 드롭다운 — 선택 즉시 "보호종료 후 경과"/"5년 기한까지" 자동 계산.
    아직 종료 안 된(예정) 케이스는 "보호종료 예정까지 남은 기간"으로 다르게 표시 (예전엔 이 구분이
    없어서 계산이 이상하게 나오는 버그가 있었음)
  - 드롭다운 선택 상태를 로컬 state로 관리 (연도만 골랐을 때 화면이 다시 placeholder로
    되돌아가던 버그 수정 — 조합이 완성되기 전엔 부모 profile 값이 빈 문자열이라 생기던 문제)
  - 기초생활수급자/차상위 질문에서 "잘 모르겠어요" 옵션 제거 (예/아니오만)
  - "지금은 해당하지 않는 지원" 목록을 사유별로 그룹핑해서 접었다 펼 수 있게 함 (`<details>`),
    빨간색 배지로 표시

### 2-3. DB 저장 (Supabase)
`supabase/schema.sql`에 전체 스키마가 있음. Supabase 대시보드 → SQL Editor에서 이 파일 전체를
실행하면 됨 (전부 `if not exists`라 재실행해도 안전).

- **공고 저장용 테이블 8개** (소스당 하나씩, 위 8개 소스와 1:1 대응):
  `announcements_central`, `announcements_local`, `announcements_gov24`,
  `announcements_housing`, `announcements_training`, `announcements_jobseeker_program`,
  `announcements_dual_training`, `announcements_youth_center`
  - 각 테이블에 원문 필드 + 온보딩 매칭용 분류 컬럼(`app/data/classify.ts`에서 계산) + 검수
    워크플로우 컬럼(`review_status` 등) 있음
  - `app/api/sync-announcements/route.ts` 호출하면 7개 소스 전부 "자립준비청년 관련" 텍스트
    필터를 거친 것만 upsert (재동기화해도 사람이 검수해둔 `review_status`는 안 건드림)
  - RLS로 `review_status='approved'`인 것만 외부 조회 가능 (즉 동기화 직후엔 화면에 안 보임 —
    의도된 설계, 사람이 검수 후 승인해야 노출)
  - 전체 8개 테이블을 한 번에 보는 `announcements_all` 뷰 있음
- **커뮤니티 테이블 2개** (오늘 추가): `community_posts`, `community_comments`
  - 로그인 없는 게시판이라 RLS로 누구나 읽고 쓰기 가능하게 열어둠 (승인 대기 없음)
  - `lib/communityDb.ts`가 이 테이블들을 CRUD
